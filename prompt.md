============================================================
AGENT DESIGN
============================================================

Implement agents as real workflow components, not just labels in UI.

------------------------------------------------------------
AGENT 1 — SITUATION AGENT
------------------------------------------------------------

Responsibilities:

- receive incident report
- normalize text
- extract structured fields
- classify incident type
- identify affected zone
- estimate affected population if supported by the source
- determine resource categories required
- produce confidence
- preserve source information

Output structured JSON.

Example:

{
  "zone_id": "ZONE_A",
  "incident_type": "flood",
  "affected_population": 1800,
  "vulnerable_population": 240,
  "needs": [
    {"type": "rescue_team", "quantity": 3},
    {"type": "water_liter", "quantity": 2500},
    {"type": "medical_kit", "quantity": 60}
  ],
  "confidence": 0.87
}

Never invent fields that cannot be inferred.

------------------------------------------------------------
AGENT 2 — NEEDS ASSESSMENT AGENT
------------------------------------------------------------

Convert incident conditions into resource needs.

Use deterministic rules for quantities wherever possible.

Example configurable rules:

- food requirement per affected person
- water requirement per affected person
- medical ratio
- rescue-team ratio
- shelter capacity requirement

Make these rules configurable in code/config rather than buried
inside prompts.

Output:

required
available
deficit
urgency

------------------------------------------------------------
AGENT 3 — PRIORITY AGENT
------------------------------------------------------------

Calculate a transparent priority score.

Use a configurable scoring model such as:

Priority =
  0.30 * Severity
+ 0.25 * Affected Population Score
+ 0.20 * Vulnerability Score
+ 0.15 * Resource Deficit Score
+ 0.10 * Time Criticality Score

Normalize to 0–100.

Show factor breakdown in the UI.

Example:

Zone A:
Severity = 10/10
Affected = high
Vulnerability = high
Deficit = severe
Priority = 96/100

Do not hide the calculation.

------------------------------------------------------------
AGENT 4 — DUPLICATE DETECTION AGENT
------------------------------------------------------------

Detect duplicate or overlapping incident reports.

Use a hybrid approach:

- geographic distance
- time similarity
- zone match
- incident type
- semantic similarity / embeddings if practical

Return:

- duplicate = true/false
- matched incidents
- similarity/confidence
- explanation

Example:

"Reports R102 and R109 likely describe the same incident:
same zone, 4-minute interval, 91% semantic similarity."

Never merge incidents automatically when confidence is low.
Use "possible duplicate" status.

------------------------------------------------------------
AGENT 5 — OPTIMIZATION AGENT
------------------------------------------------------------

This is the core decision component.

Use deterministic optimization.

Prefer Google OR-Tools where practical.

Optimization objectives should account for:

- incident priority
- unmet demand
- resource availability
- resource capability
- geographic distance
- estimated travel time
- resource scarcity
- agency constraints
- current deployment
- capacity
- route availability

Goal:

maximize critical-need coverage while minimizing response time,
constraint violations and avoidable movement.

Every result must contain:

- allocations
- unmet demand
- objective/score if available
- major constraints
- allocation rationale

Do not let an LLM choose numerical quantities.

------------------------------------------------------------
AGENT 6 — COORDINATION AGENT
------------------------------------------------------------

Translate allocation results into actionable agency tasks.

Example:

NDRF:
Deploy Rescue Team R07 to Zone A

Fire Department:
Deploy Team F03 to Zone A

NGO Alpha:
Deliver 700 food packets to Zone B

Hospital Central:
Reserve 20 emergency beds

Detect conflicts:
- unavailable resource
- double-booked team
- incompatible capability
- invalid destination
- impossible ETA

------------------------------------------------------------
AGENT 7 — REPLANNING AGENT
------------------------------------------------------------

This is a high-priority component.

Do NOT re-optimize unnecessarily for every tiny change.

Define material change thresholds.

Examples of replanning triggers:

- critical severity increase
- large population increase
- route becomes unavailable
- resource becomes unavailable
- major new need
- resource conflict
- critical-zone priority crosses another zone
- substantial deficit increase

The agent determines:

REPLAN_REQUIRED = true/false

If true:
- identify affected zones/resources
- rerun optimization
- generate delta from previous plan
- create coordination updates
- write audit event
